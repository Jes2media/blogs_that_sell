**Prompt version:** 1.0

## Your Task

Write a complete teardown of: **$ARGUMENTS**

## Required Structure

### 1. Opening (What It Is)
- Define the framework/technique/method in one clear paragraph
- No throat-clearing. Start with the definition.

### 2. Origin (Who Created It)
- Name the creator/originator
- Brief context on when and why it was developed
- Establish credibility of the source

### 3. How It Works (Step by Step)
- Break down the framework into its components
- Explain each step in practical terms
- Use subheads for each step/phase

### 4. Worked Example
**CRITICAL: This section must contain actual copy, not descriptions of copy.**

Show a complete example applying the framework. This means:
- If it's a headline formula, show the actual headline
- If it's an email structure, show the actual email
- If it's a sales letter framework, show actual paragraphs

If you cannot write a concrete, realistic example, insert:
```
<!-- JOHN: worked example needed -->
```
And stop. Do not write placeholder descriptions.

### 5. When NOT to Use This
**CRITICAL: This section is the single differentiator from competing pages. Never omit it.**

Include 2-4 specific scenarios where this framework/technique fails:
- Describe the scenario clearly
- Explain *why* it fails (mechanism, not just "it doesn't work")
- Suggest what to use instead

Example structure:
> **Don't use [framework] when...**
> - Your audience is [X] — because [reason]. Use [alternative] instead.
> - The product is [Y] — because [reason]. Consider [alternative].

## Tone and Style

- Direct and practical, not academic
- Teach by showing, not describing
- Respect the reader's time—no padding
- Be specific about applications and limitations
- Use examples from direct response (health, finance, biz-opp, coaching) not brand advertising

## What NOT to Write

- No listicles ("10 tips for using X")
- No "best tools" roundups
- No vague advice that could apply to anything
- No descriptions of what copy "should" say—show the actual copy
- No academic distance—write as a practitioner
